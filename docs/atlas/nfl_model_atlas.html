The system map

The single most important structural fact: the weekly model is downstream of the other two. It does not compute its own game environment or its own talent prior — it imports the game model's per-game predictions and the season model's per-player projection, then adds its own recency and usage layer on top. A stale rebuild anywhere upstream silently degrades it.

Data sources

Everything originates from nflverse loaders plus a handful of third-party feeds. Four stores sit between the feeds and the models: game_w_features.csv, the SQLite warehouse, an append-only market store that keeps every line and price the daily job sees (since 7 Sep), and a play-by-play store (since 27 Sep).

Known fragility. load_ff_playerids lags on rookies, so a rookie class can arrive with a null FantasyPros id and drop out of the ECR join entirely. This previously sank the whole 2026 rookie class to ~0 projected PPG; a name + position fallback in fantasy_db/R/forward.R now backstops it.

The market store. fantasy_db/market_observations.db appends every Vegas, Polymarket and Kalshi snapshot in long format and never overwrites. Before it existed, each daily run deleted the previous scrape, so no line-movement feature could ever be built. It holds 6,186 rows from 158 snapshots (7–27 Sep). It lives outside the warehouse on purpose: the Tuesday rebuild deletes fantasy_football.db and recreates it.

One play-by-play store. Eight scripts across four projects used to download nflverse play-by-play for themselves, and every download was a chance to time out. fantasy_db/pbp.db now holds 1999–2026 (1.29M plays, 147 columns, 909 MB) and build_pbp_db.R is the only script that downloads it. Everything else calls read_pbp(), which refuses a missing season, a row-count mismatch, a column outside the pinned list, or a current season more than 8 days old.

Seasons are replaced whole rather than appended by week, because nflverse revises published plays. It republished 2001, 2002 and 2024 on 13 Aug and 2020 on 26 Aug; appending would have frozen the pre-revision values. Each season records when it was pulled, so a result can name the vintage it used. Like the market store, it is a separate file so the Tuesday warehouse rebuild cannot discard it.

Trained models

Sixteen trained estimators. Every one is gradient-boosted trees or a penalised linear model — there are no neural nets in the production path (dnn_poc.R exists but nothing consumes it). The weekly quantile boosters, their active classifier and the imputation medians are cached together, keyed on the warehouse state and the feature code — so a refresh loads a fitted model and scores, without refitting and without rebuilding the training panel.

The game ensemble was retrained on 27 Sep on 2008–2026 (4,930 games), with calibration fit on 570 out-of-sample games from 2024–25. It is still GLM-only. The recalibrated EV slope dropped from 0.704 to 0.394, so the bet card now discounts the model’s raw edge by about 60% instead of 30%.

How a weekly change earns its way into production

Since mid-September every candidate change to the weekly model goes through a declared protocol in run_research.R. Each trial states its hypothesis and which stage it refits before it runs, then passes a staged funnel: a data gate, a one-season probe, a four-season screen (2019–22), and a confirm run across 2017–25 with three seeds. Only a confirm run can promote. Screens stop early when the paired gain cannot clear the practical threshold of +0.002 pinball.

The population changed too. The model now scores every rostered player for every scheduled team-week (roster_weekly_v1), not only players who later recorded a stat. That makes absolute scores from before 13 Sep incomparable with anything after.

The scoring layer between the model and a lineup

The weekly model projects half-PPR only and emits no component stats, which is fine for three of four connected leagues and wrong for the fourth. Scott Fish Bowl pays 6 per passing TD, 0.5 per first down, +1 per TE reception and +1 per TE first down, and a flat 10 for every 20-plus-yard catch. Ranking that lineup on half-PPR quietly starts the wrong players.

Rather than re-project, each player’s recent component line is scored twice — once under half-PPR, once under the league’s real rules — and the ratio rescales the model’s projection. The projected total stays the anchor; the components only decide how it is re-weighted.

All four leagues’ rules are now read from their platform rather than assumed — Sleeper exposes them directly, MFL through ff_scoring(). UNH turns out to be exactly half-PPR, so its multiplier of 1.00 is a measured fact rather than a default.

The multipliers reproduce SFB’s design intent without being told it: tight ends rescale hardest and running backs least. Players with no recent usage inherit their position’s median rather than 1.0 — defaulting them to “unchanged” in a league whose median is 1.9 would bench every rookie.

Starting slots are read, not configured

Slot rules come from each platform’s own starter definition, and the count of superflex slots is derived from the league’s QB headroom (max − min) rather than assumed to be one. SFB allows two quarterbacks and sets every positional minimum to zero, so ten starters can legitimately be ten tight ends.

Two mutually exclusive model variants. The consensus and rookie families never appear together. The default model uses ECR and drops DraftScout (ECR already prices rookies); EXCLUDE_ECR=1 inverts it, which more than doubles rookie rank correlation (0.16 → 0.40) by filling the blind spot ECR was covering. The ECR-free variant is the one that trains on fundamentals rather than reprinting consensus.

Built, measured, and kept off the site: expected fantasy points

xfp/ values every target, carry and pass attempt from play-by-play and sums them into expected half-PPR points per player-week, fit walk-forward so no season is scored by a model that saw it. It ties nflverse’s own ffopportunity on prediction (split-half .767 vs .768) and beats it on calibration (mean ratio 1.006 vs 1.018; QB top-decile bias −1.62 vs −3.35).

Against a player’s actual points, xFP is a small-sample tool. After one game it predicts rest-of-season scoring far better (r .576 vs .473); by six games the two tie, and year over year actual points are as good or better, especially at RB. Actual points carry real finishing skill that xFP deliberately removes.

Inside the weekly model it adds nothing. The model already has volume, share and snap features plus the season prior, which do the same denoising. A 9-season A/B measured CRPS +0.0008 (interval spans zero), and both xFP families stopped at screen.

How it stays current

The host is a laptop, and a laptop is not open on a schedule. The original design — two fixed slots a day, one long job per slot — assumed otherwise, and the failure mode was not subtle: over the first week of the 2026 season, 13 daily runs were scheduled, 11 started, and 6 finished clean. Two of the misses were self-inflicted, because a run that overran its slot still held the launchd label when the next one was due.

The schedule is now built the other way round. It fires often and cheaply, and each firing asks what is stale rather than which slot am I. Everything below follows from that one inversion.

What makes a refresh cheap

  • The weekly models are loaded, not fitted. The cached artifact carries the fitted boosters, the active classifier and the imputation medians, so a refresh never touches the training panel. Building that panel is 87.8 s of the 2.3 s warehouse read it sits on top of — and on a cache hit its only surviving output was a 5.3 KB table of medians. Caching that table took the step from 97 s to 7 s, with byte-identical predictions. Refitting still costs 285 s, once a week, when Tuesday’s rebuild changes what the models were trained on.
  • The feature matrix is not rebuilt. Nothing in it changes until games are played; what moves day to day reaches the models through the upcoming-week export instead.
  • The cache key is the feature code, not the column names. Hashing features.R means an edit that changes values but not column names invalidates the cache, which the previous key would have missed.
  • Scheduling is launchd, not cron — calendar intervals fire on wake and coalesce missed ones into a single event, which cron will not. StartInterval looks like the natural fit for “every hour” and is the wrong tool: its missed firings are dropped outright.

Freshness budgets

Each shared artifact declares how old it may be, and a preflight check refuses to start a run that would consume a stale one. The budgets are set by the cadence that rebuilds each artifact — a weekly artifact is legitimately six days old by Monday, so a three-day budget would block every refresh rather than catch anything.

A budget that could only fail. The season prior is built once before week 1 and is meant to stay fixed all season, so a 30-day budget guaranteed the gate would trip about four weeks in. It did: from 25 Sep every hourly refresh stopped at preflight, and the site went 53 hours without publishing, into Week 3 Sunday. Since 27 Sep the pre-week run checks that budget only for week 1.

Incremental feature builds were tried and rejected. Rebuilding a trailing 3-season window and splicing it onto the cache leaves 138 of 374 columns different — all unbounded-history counters (ref_career_n_games, coach_team_games, starter_career_games) that accumulate from 2000, so no window reproduces them. Skipping the rebuild entirely on a refresh is both correct and cheaper.

What the audit surfaced

Kept as a record rather than trimmed — what has since been closed is as informative as what is still open.

The ensemble is not an ensemble still true

fit_stacking returns a hard-coded GLM-only weight vector unless STACK_FULL=1. The decision is sound and well documented — pure GLM dropped walk-forward MAE 9.832 → 9.778 and turned the close-game bucket from 0.225 worse than Vegas to 0.036 better. But XGBoost and random forest still train on every walk-forward and every production fit, and their predictions are discarded. That is a large amount of compute buying nothing until the fallback is exercised.

Two definitions of “who wins” resolved

The margin model and the win-probability model disagree on roughly 1% of games — those near a coin flip, where the predicted margin is +0.2 while the calibrated win probability sits at 0.49. Grading keys off the margin (pred_winner), so the site's moneyline record and its win-probability bar can point at different teams in the same game.

The weekly model inherits two staleness risks it cannot see resolved

Its game-environment block reads game_w_features.csv and its talent block reads season_proj.csv. Neither carries a freshness assertion into the weekly build, so a stale upstream cache degrades weekly projections silently rather than failing loudly. The feature file is currently dated 7 Jun 2026.

Feature redundancy is a live, measured concern still open

A correlation audit of the season model's 55 features found 13 pairs at |r| ≥ 0.95, including two exact duplicates (projected_pass_rate is a verbatim copy of team_prev_pass_rate). Because colsample_bytree samples columns, duplicates claim extra draws and crowd out real signal — the documented failure mode that took team_volume_model from 0.447 to 0.410. The PRUNE flag exists to test it but is off by default.

How the resolved two were closed

The competing moneyline definitions were collapsed into one: model_pick_winner() now lives beside model_pick_ats() in a shared module and keys off the predicted margin, matching what grading has always scored. Anything displaying a pick uses it, so a card can no longer contradict its own win/loss mark.

The weekly model’s invisible dependencies are now explicit. Its two upstream inputs are declared edges in a {targets} graph, so changing the season projection marks the board, the week’s reports and the regression gate out of date and nothing else. Joins that feed it assert their own match rates, and a run refuses to start on a stale input. The failure that motivated this — week-one projections collapsing onto the positional median when the talent prior silently matched nothing — now stops the pipeline with the match rate in the message.

The scheduled retrain never completed fixed · first run pending

No scheduled retrain had succeeded. The failing season changed every time, which pointed away from any one file: each run re-downloaded all of 2000–2026 overnight, and some season always hit the 60-second download timeout. The feature build now reads the play-by-play store, which loads all 27 seasons in about 19 seconds with no network. The first scheduled run on it is the next 03:00 firing. The production ensemble in use was rebuilt by hand on 27 Sep, during a daily refresh.

Daily downloads still run on a 60-second timeout open

The 27 Sep 15:33 refresh hit its four-hour deadline after nflverse downloads stalled: the upcoming-week step failed after 33 minutes and a roster fetch timed out. The retrain loader now raises its timeout, but the daily steps’ loaders do not.

The Q&A tool’s play-by-play copy is out of date open

Cross-checking the new store against nflverse_qa’s DuckDB copy matched row counts in all 27 seasons but not EPA in three (2001, 2002, 2020). The store matches today’s nflverse; the DuckDB copy was built from 3 Aug files and missed both August republishes, so questions answered from it use pre-revision EPA.

Every daily refresh failed for 14 hours resolved

From 08:58 to 22:20 on 27 Sep the critical upcoming-week step failed in every scheduled refresh. An edit to refresh_live_features.R loaded ensemble_lib.R by a relative path, which works from the project folder by hand but not from the folder launchd starts runs in. The fix is the same two lines its sibling scripts already used. The general lesson: test any script a scheduled job runs from the scheduler’s working directory.

League data missing from a clean run resolved

The 27 Sep refresh exited clean but published three leagues with missing data. The MFL case was not a feed change: before kickoff MFL correctly lists players without scores, and ffscrapr’s ff_starters() drops the absent score column and then fails converting it, on every pre-week run. MFL set lineups are now read straight from its weeklyResults endpoint. Two Sleeper leagues published without draft picks because neither has traded a pick: Sleeper returns an empty list, and ffscrapr fails on it. Picks are now built from each league’s own settings, and only for keeper and dynasty leagues; #SFB16 is redraft and owns none.

A preseason artifact on an age budget resolved

Covered under freshness budgets above: 53 hours offline, fixed on 27 Sep by gating the season prior’s age in week 1 only.

New: the feature build does not decompose by design

Measured while trying to make daily runs cheaper: 138 of the 374 feature columns are unbounded-history counters accumulating since 2000, so the matrix cannot be rebuilt in windows. This is a real constraint on how the pipeline can ever be parallelised or incrementalised, not a defect — recorded here so it is not rediscovered a third time.

Two-stage fit, so the calibration set is never in-sample. Base learners train on 2008–2023 (4,327 games) and predict on 2024–2025 (570 games); the stacking weights, σ and Platt are fit on those genuinely out-of-sample predictions. Only then are the learners retrained on the full window for production. As of 27 Sep that full window is 2008–2026 (4,930 games). The two windows overlap as date ranges but never as a single fit.
